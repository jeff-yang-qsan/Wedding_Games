# Feature Specification: 數字抽籤遊戲

**Feature Branch**: `001-number-lottery-game`  
**Created**: 2026-01-12  
**Status**: Draft  
**Input**: User description: "我要撰寫一個小遊戲, 使用瀏覽器呈現, 必須能快速部屬, 不要有太複雜的環境建置過程, 遊戲人數為五人, 使用各自的手機瀏覽器進行數字抽籤, 數字的範圍為 0 ~ 100, 主持人也會準備一個介於 0 ~ 100 的數字, 投影幕上會顯示五個數字欄位與對應參賽者的暱稱, 抽籤結束後, 會將每位參加者抽中的數字減去主持人準備的數字, 如此重複五次, 最後數字最大的參賽者會獲得一份小禮物"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 遊戲設置與參賽者註冊 (Priority: P1)

主持人建立新遊戲並讓五位參賽者透過手機加入遊戲，每位參賽者輸入自己的暱稱後等待遊戲開始。

**Why this priority**: 這是遊戲的基礎功能，沒有參賽者註冊就無法進行任何遊戲活動。這個故事提供了最基本的可用產品 - 一個可以讓多人加入的遊戲房間。

**Independent Test**: 可以透過主持人建立遊戲、五個人用不同手機加入並輸入暱稱來完整測試，驗證多人連線和暱稱顯示功能是否正常運作。

**Acceptance Scenarios**:

1. **Given** 主持人開啟遊戲網頁，**When** 點擊「建立新遊戲」，**Then** 系統生成4-6位數字遊戲房間代碼並顯示在投影幕上
2. **Given** 遊戲房間已建立，**When** 參賽者在手機瀏覽器輸入房間代碼，**Then** 成功進入遊戲並可輸入暱稱
3. **Given** 參賽者已進入遊戲，**When** 輸入暱稱並確認，**Then** 暱稱顯示在投影幕的對應欄位中
4. **Given** 已有參賽者加入，**When** 第六位參賽者嘗試加入，**Then** 系統顯示「遊戲人數已滿」訊息

---

### User Story 2 - 單輪抽籤與計分 (Priority: P1) 

參賽者在手機上進行一輪數字抽籤（0-100），主持人設定目標數字，系統計算每位參賽者的得分（抽中數字減去主持人數字）並顯示結果。

**Why this priority**: 這是遊戲的核心機制，包含抽籤、計分邏輯，是最小可行產品必須具備的功能。完成這個故事後就有一個可以玩的完整遊戲。

**Independent Test**: 可以透過五位參賽者各自在手機上抽數字，主持人輸入目標數字，驗證計分邏輯和結果顯示是否正確。

**Acceptance Scenarios**:

1. **Given** 五位參賽者都已加入遊戲，**When** 主持人啟動第一輪抽籤，**Then** 所有參賽者的手機顯示抽籤按鈕
2. **Given** 抽籤已開始，**When** 參賽者點擊抽籤按鈕，**Then** 產生0-100隨機數字並顯示在手機上
3. **Given** 所有參賽者都已抽籤，**When** 主持人輸入目標數字並確認，**Then** 系統計算每位參賽者得分（參賽者數字 - 主持人數字）
4. **Given** 計分完成，**When** 系統顯示本輪結果，**Then** 投影幕顯示每位參賽者的抽中數字、目標數字、和得分

---

### User Story 3 - 多輪遊戲與最終排名 (Priority: P2)

重複進行五輪抽籤，累計每位參賽者的總得分，最後顯示最終排名並宣布獲勝者。

**Why this priority**: 完整的遊戲體驗需要多輪遊戲和最終結果，但單輪遊戲已經可以提供基本價值。

**Independent Test**: 可以透過進行完整的五輪遊戲，驗證得分累計、排名計算和獲勝者宣布功能。

**Acceptance Scenarios**:

1. **Given** 第一輪遊戲結束，**When** 主持人啟動下一輪，**Then** 系統重置抽籤狀態但保留累計分數
2. **Given** 遊戲進行中，**When** 完成任一輪，**Then** 投影幕顯示當前累計排名
3. **Given** 已完成五輪遊戲，**When** 最後一輪計分完成，**Then** 系統顯示最終排名和獲勝者慶祝畫面
4. **Given** 遊戲結束，**When** 顯示最終結果，**Then** 明確標示獲勝者並提醒頒發小禮物

---

### User Story 4 - 遊戲狀態管理與重置 (Priority: P3)

主持人可以查看遊戲進度、重新開始遊戲或處理異常情況（如參賽者中途離開）。

**Why this priority**: 這些是增強使用體驗的輔助功能，但不影響核心遊戲流程。

**Independent Test**: 可以透過模擬各種異常情況和重置操作來驗證系統的穩定性。

**Acceptance Scenarios**:

1. **Given** 遊戲進行中，**When** 主持人查看遊戲狀態，**Then** 顯示當前輪數、已抽籤人數、累計分數等資訊
2. **Given** 遊戲任何階段，**When** 主持人選擇重新開始，**Then** 系統清除所有數據並回到初始狀態
3. **Given** 參賽者中途離開，**When** 其他人繼續遊戲，**Then** 系統標記該參賽者為離線但保留其數據

## Clarifications

### Session 2026-01-12

- Q: 當多位參賽者最終得分相同時如何決定獲勝者？ → A: 總分相同時所有參賽者並列冠軍，都獲得小禮物
- Q: 當主持人忘記設定目標數字時如何提醒？ → A: 系統自動提醒主持人輸入目標數字，阻擋計分直到輸入完成
- Q: 當參賽者抽中的數字小於主持人數字時，得分為負數如何處理？ → A: 得分允許為負數，正常顯示負數結果
- Q: 當參賽者在抽籤過程中網路中斷如何處理？ → A: 參賽者網路中斷時保留其已有數據，允許重新連接繼續遊戲
- Q: 房間代碼使用什麼格式？ → A: 房間代碼使用4-6位數字，簡單易記但仍有足夠唯一性

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須支援同時最多五位參賽者透過手機瀏覽器參與遊戲
- **FR-002**: 系統必須提供投影幕顯示介面，清楚顯示所有參賽者暱稱和遊戲狀態  
- **FR-003**: 參賽者必須能透過手機產生0到100之間的隨機數字
- **FR-004**: 主持人必須能設定0到100之間的目標數字
- **FR-005**: 系統必須正確計算得分（參賽者數字減去主持人數字）並顯示結果
- **FR-006**: 系統必須支援完整進行五輪遊戲並累計總得分
- **FR-007**: 系統必須在遊戲結束時明確顯示獲勝者，總分相同時所有參賽者並列冠軍
- **FR-008**: 系統必須使用靜態檔案部署，無需複雜的伺服器環境設定
- **FR-009**: 參賽者必須能在遊戲開始前輸入並修改自己的暱稱
- **FR-010**: 主持人必須能查看當前遊戲狀態並控制遊戲進程
- **FR-011**: 系統必須在計分前確保主持人已設定目標數字，未設定時阻擋計分並顯示提醒
- **FR-012**: 系統必須在網路中斷時保留參賽者數據，支援重新連接繼續遊戲

### Key Entities

- **遊戲房間**: 包含4-6位數字房間代碼、當前輪數、遊戲狀態（等待/進行中/結束）
- **參賽者**: 包含暱稱、當前抽中數字、累計得分、連線狀態
- **遊戲輪次**: 包含輪數、主持人目標數字、所有參賽者該輪得分
- **遊戲結果**: 包含最終排名、獲勝者資訊、各輪詳細記錄

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 五位參賽者能在30秒內成功加入遊戲並完成暱稱設定
- **SC-002**: 單輪抽籤從開始到顯示結果能在60秒內完成
- **SC-003**: 完整五輪遊戲能在10分鐘內順利進行完畢
- **SC-004**: 系統能在網路不穩定環境下正常運作，至少支援3G網路連線速度
- **SC-005**: 遊戲介面在手機和投影設備上都能清晰顯示，文字大小適中易讀
- **SC-006**: 部署流程從下載到運行能在5分鐘內完成，無需額外軟體安裝
